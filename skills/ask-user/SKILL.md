# Ask User — 反問使用者的規範

使用 `ask_user(question: str)` 工具，在介面上彈出輸入框向使用者詢問補充資訊。工具會回傳使用者的回答。

## 呼叫前必做：先讀附件、再回頭找

**呼叫 `ask_user` 之前，一定要依序完成：**

1. **有附件就先讀附件**：依 `read-attachments` skill 完整讀取所有附件（檔案、圖片、截圖、貼上的程式碼或 DDL）
2. **回頭找對話**：使用者之前說過的內容也算已提供
3. **列出還缺什麼**：只有附件和對話中**都找不到**、而且猜錯會讓答案錯誤的資訊，才可以問

- 附件中寫明的內容一律視為「使用者已提供」，**不可以再問**
- 使用者說「如附件」「看附檔」「如圖」時，答案就在附件裡，先讀，不要問
- 附件只有一部分讀不到（圖片某行模糊、檔案內容中斷）時，只問讀不到的那一部分，不要要求重傳全部

## 何時呼叫

先問自己：**「如果我猜錯，答案會不會變得沒用或錯誤？」** 答案是「會」才呼叫。

應該呼叫的情況：
- 缺少目標或用途（例：「幫我寫個程式」但沒說做什麼）
- 缺少會改變做法的環境資訊：語言、版本、作業系統、框架、資料庫（**附件和對話中都找不到時**）
- 有多種合理解讀，且各解讀的答案差異很大
- 缺少必要的輸入資料（例：要分析檔案但沒給內容）。**已上傳附件就不算缺少**
- 附件無法讀取，或內容明顯不完整，且缺少的部分會影響答案
- 涉及不可逆或高風險操作（刪除、覆蓋、送出），需要確認

## 何時不要呼叫

- 次要細節：用合理預設值，並在回答開頭寫「假設：…」
- 使用者已經在對話中提供過的資訊（先回頭找）
- **附件中已經有的資訊**（先讀附件）
- 一般知識問題、定義、概念解釋
- 只是想確認使用者「要不要」你繼續：直接做
- 同一個問題已經問過，使用者也回答了

## 如何提問

1. **一次只呼叫一次**，把所有關鍵問題合併在同一個 `question` 裡，最多 3 個問題。
2. 問題要**具體**，盡量附選項，讓使用者能快速回答：
   - ✅ 「你用的是 Oracle 還是 MySQL？版本大約是？」
   - ❌ 「可以提供更多資訊嗎？」
3. 依重要性排序，最關鍵的放第一個。
4. 可簡短說明為什麼需要這個資訊（一句話以內）。
5. 使用與使用者相同的語言提問。
6. **有附件時，先用一句話說明已從附件取得哪些資訊**，讓使用者知道附件有被讀過，再列出還缺的問題。

`question` 格式範例：
```
為了給你正確的寫法，需要確認：
1. 資料庫是 Oracle 還是 MySQL？
2. 要回傳單筆還是多筆結果？
```

有附件時的格式範例：
```
已從附件 emp.sql 取得 EMP 表的欄位與主鍵，還需要確認：
1. 「離職員工」是用哪個欄位判斷？（例如 status = 'N' 或 leave_date 有值）
2. Oracle 版本是 11g 還是 12c 以上？
```

## 收到回答後

依工具回傳內容處理：

| 情況 | 處理方式 |
|---|---|
| 工具回傳 `[STOP]`（使用者取消或未回答） | 立即停止。只輸出工具指定的那一句話，不回答原始請求、不猜測、不產生程式碼、不再次呼叫 ask_user |
| 使用者明確回答「不知道」「你決定」「都可以」 | 用最常見的預設值完成回答，並在開頭註明「假設：…」 |
| 使用者有回答 | 直接依回答完成任務，不重複確認已回答的內容 |

其他規則：
- 若回答後仍有關鍵缺漏，最多再呼叫一次 ask_user。
- 第二次之後仍不足：一般任務用合理假設完成並註明；**不可逆或高風險操作則不執行**，改為說明還缺什麼資訊。
- 回答時直接進入內容，不要說「根據上下文」「根據工具結果」「使用者之前的請求是…」，也不要複述使用者的回答。唯一例外：有附件時，依 `read-attachments` skill 在開頭用一兩行列出讀到的附件。

## 範例

**使用者**：幫我寫一個排程備份的腳本
**判斷**：缺作業系統、備份對象，會完全改變寫法 → 呼叫
```
ask_user("為了寫出可用的腳本，需要確認：\n1. 作業系統是 Windows 還是 Linux？\n2. 要備份的是資料夾還是資料庫？\n3. 多久備份一次？")
```

**使用者**：Python 怎麼讀 CSV？
**判斷**：一般問題，用 csv 或 pandas 都能答 → 不呼叫，直接回答並提兩種做法

**使用者**：把 users 表裡的舊資料刪掉
**判斷**：「舊」的定義不明，且刪除不可逆 → 呼叫
```
ask_user("「舊資料」的條件是什麼？例如：建立時間早於某日期、狀態為停用，或其他條件？")
```
若使用者取消 → 只輸出「已取消，需要時請補充資訊再問我。」，不產生任何 DELETE 語句。

**使用者**：（上傳 emp.sql）幫我寫一個查詢各部門人數的 SQL
**判斷**：附件已有表名與欄位，Oracle 版本不影響這個查詢 → 不呼叫，直接用附件中的實際欄位寫 SQL

**使用者**：（上傳程式碼截圖）這段為什麼會錯？
**判斷**：先讀截圖。截圖中已有程式碼與錯誤訊息 → 不呼叫，直接分析；若只有第 12 行看不清楚 → 呼叫，只問那一行
```
ask_user("已讀取截圖中的程式碼，但第 12 行看不清楚，可以貼上第 12 行的文字嗎？")
```

**使用者**：（上傳需求規格.pdf）照附件幫我設計資料表
**判斷**：需求在附件中 → 不呼叫「請提供需求」；只有附件沒寫、且會改變設計的事項才問
